Models / fields

Functional fields.

A small vocabulary for declaring common Django fields without giving up the models, migrations, and behavior you already trust.

trim.models.fields Compatible with Django fields

The idea

Django, with the repetitive names trimmed away.

Every helper shadows a standard Django field. The result is deliberately familiar: use a concise function while designing, then swap back to Django's built-in field whenever you need to.

That makes fields useful during the first pass of a project, when the model shape is changing quickly and clarity matters more than ceremony.

Integrate

One import, then keep modelling.

Add django-trim to your project and import the field helpers from the models package.

models.py
from django.db import models
from trim.models import fields

class StockChange(models.Model):
    stockcount = fields.fk(StockCount)
    from_count = fields.int(0)
    to_count = fields.int(1)
    created, updated = fields.dt_cu_pair()

A useful pattern

Pairs for the moments worth remembering.

dt_cu_pair() creates the conventional created and updated fields together, keeping audit timestamps consistent across your models.

model timestamps
created, updated = fields.dt_cu_pair()

Keep your vocabulary

Aliases make the helpers feel like yours.

Field helpers include flipped aliases, so you can choose the naming direction that reads naturally in your project.

equivalent names
user = fields.user_fk()
owner = fields.fk_user()
