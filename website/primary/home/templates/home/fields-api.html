Models / fields / API

The fields API.

A practical reference for importing and using the most useful helpers from trim.models.fields.

Copy the code Use familiar Django models

01 / Import

Bring the field vocabulary into your model.

The public entry point is the fields object from trim.models. Each helper returns a normal Django model field, so migrations and model behavior remain part of Django's usual workflow.

models.py
from django.db import models
from trim.models import fields

02 / Tiny example

Start with a model that reads like its intent.

This example uses a relation, a pair of integer defaults, and automatic creation and update timestamps.

models.py
class StockChange(models.Model):
    stockcount = fields.fk(StockCount)
    from_count = fields.int(0)
    to_count = fields.int(1)
    created, updated = fields.dt_cu_pair()

The helper names describe the field’s role, while positional and keyword arguments continue through to the underlying Django field.

04 / Parameters

Pass the arguments you already know.

Helpers accept the arguments used by their Django equivalents. Defaults can be supplied directly, and keyword options such as blank, null, or on_delete remain available.

Default values

Give a field a default without writing the field class.

eggs = fields.int(6)
active = fields.bool_true()
Field options

Continue to use normal Django keyword options.

title = fields.chars(
    max_length=120,
    blank=True,
)
Relations

Provide the related model and deletion policy.

owner = fields.fk(
    "accounts.User",
    on_delete=models.CASCADE,
)

A little more power

Build a generic relation in one declaration.

The any helper creates the three pieces needed to associate a model with an arbitrary object. Give the group a prefix to keep the generated names clear.

generic association
unit, unit_content_type, unit_object_id = fields.any(
    prefix="unit",
)
